# EYE3 Vision — agent guide

Read by OpenCode, Claude Code and other coding agents.

## What this is
A single static page (`index.html`): an on-device visual workspace. No backend, no API keys, no build step.

## Run
`python3 -m http.server 8080`, then open http://localhost:8080 (the camera needs localhost or HTTPS).

## Structure (all in `index.html`)
- CSS tokens on `:root`; keep the dark/crimson "red portal" look (near-black `#050101`, accent `#ff263f`, soft accent `#ff7a8a`, text `#fff5f6`, muted `#b9a9ac`). The eye-in-diamond mark is inline SVG; no personal photos or base64 images are committed (a personal photo theme stays in the browser's localStorage).
- One IIFE script. Engines load lazily through `useEngine()`: COCO-SSD (`getDetector`), MobileNet (`getClassifier`), Tesseract (`getOcr`), exifr. Versions are pinned in `LIBS`.
- Views: Image inspector, Side-by-side compare, Visual library, Connect TV (`setView`). Connect TV is a mirroring helper (Miracast; iPhone + Philips Saphi needs HDMI or a stick, since Saphi has no browser, AirPlay for Apple TV) with a QR link, a TV-browser route and presentation mode; no native TV app. It also has built-in casting: receiver overlay `#receiver`, sender `connectSender`, scanner.

## EYE3 Home
`home/index.html` is a fullscreen launcher for a laptop/PC connected to the TV over HDMI. Unlike the TV portal it runs in a MODERN browser, so modern CSS/JS is fine. Keyboard/remote nav (arrows, Enter, Back/Esc, F=fullscreen). Opens with a once-per-session splash (`?splash=0` skips it) and a "See beyond" hero. Live TV uses hls.js (pinned) with a native-HLS fallback; adult groups filtered; the viewer's playlist is in localStorage only. Tiles open the main app (`index.html?tv=1`), YouTube leanback, a web iframe, and info overlays. Also: Radio (radio-browser.info directory, https-only streams), My media (USB drive or files via the file picker, played in place with object URLs, never uploaded), a free-list picker in Live TV (iptv-org categories, M3UPT; adult groups stay filtered), a drifting-clock screensaver (key `S`, Settings sets the idle time; it never starts during playback) and a screen wake lock while media plays. Home also has a Phone remote receiver (Settings → Phone remote; same ntfy `eye3rc-<code>` topic scheme as the portal, code kept in localStorage `eye3.home.rc`, `?signal=` honoured on localhost only). It accepts only a fixed whitelist of navigation/media commands (arrows, ok, back, home, chup/chdown, digits, tv/radio/media, volup/voldown/mute, play, sleep, saver); never add commands that take text, URLs or files. A sleep timer (key `Z`, chip in the footer) stops playback and starts the screensaver.

## IPTV accounts and EYE3 Link
Home → Live TV → IPTV accounts (also Settings) lets a viewer add their OWN M3U link, Xtream Codes login or MAG/Stalker portal (address + MAC). A web page cannot read those providers (CORS, http streams on an https page, custom headers), so `tools/eye3-link.py` (Python 3, standard library only, `tools/README.md` for viewers) runs on the viewer's computer at `127.0.0.1:8765`: it fetches/parses the account (`/api/m3u`, `/api/xtream`, `/api/stalker`), creates Stalker play links on demand and proxies streams (`/stream`, rewriting HLS playlists). Rules: bind to loopback only; answer only allow-listed origins (`https://j-janko420.github.io`, localhost, plus `--origin`); check the `Host` header; every `/stream` and `/stalker/play` URL carries a per-run secret token, so other sites cannot use it as a proxy; never log or persist credentials in the helper; account details live only in the viewer's `localStorage` (`eye3.home.accts`); `--proxy` (HTTP proxies only) lets a viewer route their own accounts through a VPN/proxy they already have; EYE3 itself must never claim to include or provide a VPN, and Home's Help screen (Settings → Help, VPN & useful tools) says so plainly; never commit anyone's credentials, MAC or provider URLs to this repo; adult groups stay filtered; do not make `--insecure` the default. `python3 tools/test_eye3_link.py` runs offline against mock Xtream/Stalker/HLS servers. The TV portal cannot use the helper: it only offers "Add Xtream Codes login", which just builds a `get.php` playlist link. Two accounts may offer the same stream; do not de-duplicate across a viewer's own accounts.

## Language (English only)
EYE3 Home runs in **English only** by request: there is no language setting, `startLang()` ignores the browser language and clears any saved `eye3.home.lang`. The paragraph below describes the dormant engine, kept so a language can be switched back on later; do not re-add a visible language switch without the owner asking.

EYE3 Home has a small translation engine in `home/index.html` (`applyLang`, `lookup`, a MutationObserver) and dictionaries in `home/i18n-fr.js` and `home/i18n-ar.js` (loaded on demand, cached by `home/sw.js`). The app keeps its English strings in code; the engine translates text nodes and `placeholder` / `title` / `aria-label` / `alt` attributes **as they are created**, matching the whole English string (whitespace collapsed) against `exact`, then `patterns` (regex → function, for messages with numbers or names), then bullet and " · " parts. Switching back to English restores the original text exactly. Language comes from Settings → Language (stored in `eye3.home.lang`) or, the first time, the browser language; unsupported languages stay English; Arabic sets `dir="rtl"` (layout uses CSS logical properties; tracked letter-spacing is removed for Arabic). Rules: mark **data** (channel, account, station and file names, the clock/date, example URLs, brand and tool names, the pairing code) with `translate="no"` (helper `nt()`), because a channel called "News" must never be translated; use `tr()` for browser `prompt`/`alert` text; when you add or change a visible English string, add the same key to **both** dictionary files and check Home in French and Arabic for leftover English (loop over the screens and list text nodes that were not translated). Option `value`s must stay English: only their visible text is translated. Translations were written by an AI and should be reviewed by a native speaker. The phone remote, the TV portal, Bridge and the main EYE3 Vision app are not translated yet.

Home also honours direct links `home/?add=m3u|xtream|mag` (opens IPTV accounts on that type) and `?add=playlist` (opens the Playlist maker). They only open the form: never prefill or save anything from the URL, and never add a link for the Explicit section.

## Playlist maker
Live TV → Playlist maker (`#ov-maker`) lets a viewer add their own channels by hand (name, link, group, logo, tvg-id), import an M3U file, and export an `.m3u` (favourites, the channels listed in Live TV, or their own channels) to use in SS IPTV, VLC or TiviMate. Stored in `eye3.home.mychannels`, shown as the own category "My channels". Rules: nothing is uploaded; exports never include streams from the viewer's accounts (`LINK_BASE` URLs carry a private token); adult entries are neither listed nor exported while the Explicit section is locked, and import messages count visible channels only; attribute values are sanitised so a name cannot break the file; no DRM / license-key fields (EYE3 cannot play DRM and must not help configure protected streams). The idea came from the MIT-licensed imrsaleh/Easy-M3U-Playlist-Creator (a Tkinter tool); no code was copied.

## Explicit (18+) section and connection checks
- The explicit section is hidden on purpose: it has **no visible button**. It opens by double-clicking (or double-tapping) the eye logo (`#brand`) or with Shift+X, shows a dialog (`#ov-explicit`) with an "I am 18 or older" box and an optional PIN, and unlocks only for the current page load (a reload, the screensaver or the sleep timer lock it again). The PIN is stored salted + SHA-256 in `eye3.home.pin`; it stops casual use and is not strong security. Do not add a visible entry point for it.
- It reveals adult groups of the viewer's **own** accounts and playlists only. EYE3 never ships, lists or links adult channels: the public catalogue builder drops them, and the repo must not contain adult sources. EYE3 Link flags adult entries (`x: true`) instead of dropping them; Home keeps flagged channels out of every list, count, group, country, favourite and search unless the section is unlocked, and shows them only inside the "Explicit (18+)" category. Never leak their number while locked (the account row counts visible channels only). The TV portal still filters adult entries completely.
- "Check from my connection" (Live TV) asks EYE3 Link (`/api/probe`) whether each listed stream really delivers video from the viewer's own connection (through their `--proxy`/VPN if set), remembers the result for 24 hours in `eye3.home.health`, and can hide channels that failed. "Where is my connection?" (`/api/where`) asks ipinfo.io only when clicked. This is how geo-blocks are handled honestly: EYE3 does not include a VPN.

## Channel catalogue
`scripts/build_channels.py` + `.github/workflows/channels.yml` rebuild the free catalogue weekly (and on demand) on a GitHub runner, which has real internet: it reads the public iptv-org `index.m3u` and the Free-TV/IPTV `playlist.m3u8` (country-grouped; country names mapped to codes, categories guessed from names), keeps only HLS streams, drops adult channels, geo-blocked entries and streams that need custom headers, probes every stream (playlist, then the first variant, then its newest video segment) and keeps only the ones that really deliver video; links whose signed token (`exp=`) has expired are dropped. Output (committed by the workflow): `iptv/eye3-full.m3u` (for SS IPTV / Smart STB / TiviMate, all working channels grouped by category) and `iptv/channels.json` (compact, read by EYE3 Home and the TV portal; field `s`=1 means https, which is all a browser on https can play). The builder refuses to publish if fewer than 50 channels answer. `python3 scripts/test_build_channels.py` tests the probe offline. Do not hand-edit these generated files; change the script. Do not add paid, pirated or adult sources. `iptv/eye3.m3u` stays as the small hand-picked starter list.

## TV portal
`portal/c/index.html` is the Smart STB/MAG IPTV portal and `portal/check/index.html` is the TV capability check. Both must stay ES5 (no arrow functions, let/const, template literals, `?.`, `??`, spread) with plain CSS (no custom properties, flex, grid, `inset`, `min()`), because TV engines are old. The menu has Live TV (picks), All channels (category browser) and By country, both fed by `../../iptv/channels.json` over same-origin XHR, with Back returning to the previous list and a fallback to the built-in channels if the catalogue cannot load. Play through `gSTB.Play('ffmpeg ' + url)` when the MAG API exists, else HTML5 video. The portal also has a Phone remote receiver: it listens on an ntfy topic (`eye3rc-<code>`) via EventSource (XHR-poll fallback) and applies commands by synthesizing `document.onkeydown`; `remote/index.html` is the phone sender (POSTs plain commands). Keep both ES5-safe where they touch the portal. Only free public streams and the viewer's own playlist; never bundle paid or pirated sources.

## Rules
- Images must never be uploaded to a server. Keep analysis in the browser. Casting sends frames only peer-to-peer over the LAN (`RTCPeerConnection` with `iceServers: []`, never add STUN/TURN); ntfy carries only AES-GCM ciphertext keyed by the pairing code.
- Never auto-connect a sender from a `?join=` link; require a button press. The `?signal=` and `?pairTimeout=` overrides are honored on localhost only.
- Pin CDN versions exactly; never use `@latest`.
- Render untrusted text (file names, EXIF, OCR) with `textContent`, never `innerHTML`.
- A failed engine load must degrade to an inline message, not break the page.
- Deploys via `.github/workflows/pages.yml` on push to `main`.
