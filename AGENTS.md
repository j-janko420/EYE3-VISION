# EYE3 Vision — agent guide

Read by OpenCode, Claude Code and other coding agents.

## What this is
A single static page (`index.html`): an on-device visual workspace. No backend, no API keys, no build step.

## Run
`python3 -m http.server 8080`, then open http://localhost:8080 (the camera needs localhost or HTTPS).

## Structure (all in `index.html`)
- CSS tokens on `:root`; keep the dark/crimson "red portal" look (near-black `#050101`, accent `#ff263f`, soft accent `#ff7a8a`, text `#fff5f6`, muted `#b9a9ac`). The eye-in-diamond mark is inline SVG; no personal photos or base64 images are committed (a personal photo theme stays in the browser's localStorage).
- One IIFE script. Engines load lazily through `useEngine()`: COCO-SSD (`getDetector`), MobileNet (`getClassifier`), Tesseract (`getOcr`), exifr. Versions are pinned in `LIBS`.
- Views: Image inspector, Side-by-side compare, Visual library, Connect TV (`setView`). Connect TV is a mirroring helper (Miracast; iPhone + Philips Saphi needs HDMI or a stick, since Saphi has no browser, AirPlay for Apple TV) with a QR link, a TV-browser route and presentation mode; no native TV app. It also has built-in casting: receiver overlay `#receiver`, sender `connectSender`, scanner.

## EYE3 Home
`home/index.html` is a fullscreen launcher for a laptop/PC connected to the TV over HDMI. Unlike the TV portal it runs in a MODERN browser, so modern CSS/JS is fine. Keyboard/remote nav (arrows, Enter, Back/Esc, F=fullscreen). Opens with a once-per-session splash (`?splash=0` skips it) and a "See beyond" hero. Live TV uses hls.js (pinned) with a native-HLS fallback; adult groups filtered; the viewer's playlist is in localStorage only. Tiles open the main app (`index.html?tv=1`), YouTube leanback, a web iframe, and info overlays. Also: Radio (radio-browser.info directory, https-only streams), My media (USB drive or files via the file picker, played in place with object URLs, never uploaded), a free-list picker in Live TV (iptv-org categories, M3UPT; adult groups stay filtered), a drifting-clock screensaver (key `S`, Settings sets the idle time; it never starts during playback) and a screen wake lock while media plays. Home also has a Phone remote receiver (Settings → Phone remote; same ntfy `eye3rc-<code>` topic scheme as the portal, code kept in localStorage `eye3.home.rc`, `?signal=` honoured on localhost only). It accepts only a fixed whitelist of navigation/media commands (arrows, ok, back, home, chup/chdown, digits, tv/radio/media, volup/voldown/mute, play, sleep, saver); never add commands that take text, URLs or files. A sleep timer (key `Z`, chip in the footer) stops playback and starts the screensaver.

## IPTV accounts and EYE3 Link
Home → Live TV → IPTV accounts (also Settings) lets a viewer add their OWN M3U link, Xtream Codes login or MAG/Stalker portal (address + MAC). A web page cannot read those providers (CORS, http streams on an https page, custom headers), so `tools/eye3-link.py` (Python 3, standard library only, `tools/README.md` for viewers) runs on the viewer's computer at `127.0.0.1:8765`: it fetches/parses the account (`/api/m3u`, `/api/xtream`, `/api/stalker`), creates Stalker play links on demand and proxies streams (`/stream`, rewriting HLS playlists). Rules: bind to loopback only; answer only allow-listed origins (`https://j-janko420.github.io`, localhost, plus `--origin`); check the `Host` header; every `/stream` and `/stalker/play` URL carries a per-run secret token, so other sites cannot use it as a proxy; never log or persist credentials in the helper; account details live only in the viewer's `localStorage` (`eye3.home.accts`); `--proxy` (HTTP proxies only) lets a viewer route their own accounts through a VPN/proxy they already have; EYE3 itself must never claim to include or provide a VPN, and Home's Help screen (Settings → Help, VPN & useful tools) says so plainly; never commit anyone's credentials, MAC or provider URLs to this repo; adult groups stay filtered; do not make `--insecure` the default. `--dns cloudflare|google|URL` is an opt-in DNS-over-HTTPS fallback used only when the system lookup fails (it patches `socket.getaddrinfo`; the resolvers are reached by IP; never enable it by default, since it would send provider host names to a third party); it is not a VPN and must not be described as one. `python3 tools/test_eye3_link.py` runs offline against mock Xtream/Stalker/HLS servers. The TV portal cannot use the helper: it only offers "Add Xtream Codes login", which just builds a `get.php` playlist link. Two accounts may offer the same stream; do not de-duplicate across a viewer's own accounts.

## Movies & series on demand
Live TV → Movies & series (`#ov-vod`, also `home/?add=movies`) lists the movies and series of the viewer's OWN Xtream Codes accounts. EYE3 Link serves `/api/vod` (compact list, `kind=movie|series`), `/api/vod/series` (seasons and episodes) and `/api/vod/play` (a token-protected `/stream` link; the proxy forwards `Range`, so seeking works). The list is read once per account and kind and kept in memory only. Only the file types a browser plays (mp4/webm) work in the page; for `.mkv` and similar the screen says to use VLC. Adult titles are flagged `x` by Link and follow the same rule as live channels: hidden everywhere unless the Explicit section is unlocked, then shown only in its category. Never commit a viewer's server, username or password (tests use mock servers only).

"Free movies" (button in the same screen, no account and no EYE3 Link) lists public-domain feature films from the Internet Archive: the browser calls `archive.org/advancedsearch.php` (collection `feature_films`, adult subjects and titles excluded, paged, genre via `subject:`) and `archive.org/metadata/<id>`, picks the h.264 mp4 (else any mp4/webm/ogv, no trailers) and plays it from `archive.org/download/`. The API answers with `Access-Control-Allow-Origin: *` (checked from a GitHub runner). Keep it to that curated collection; do not add scraped or unlicensed movie sources, and never list adult titles from it.

## Pro player features (guide, recents, resume)
- **TV guide:** Xtream live channels carry their stream id (`e` from EYE3 Link, `eid` in Home). Playing one asks `GET /api/epg?id=` (Xtream `get_short_epg`, titles base64-decoded, bad rows skipped, ids must be numeric) and adds "Now: … (until hh:mm) · Next: … (hh:mm)" to the channel label; cached 2 minutes and refreshed when the current programme ends. Channels without a guide just show their name.
- **Recently watched:** category "🕘 Recently watched" (last 30, newest first, `eye3.home.recent`). Keyed by `category|name`, not by URL, because EYE3 Link URLs change at every start. Adult channels are never recorded.
- **Resume:** `eye3.home.resume` keeps the position (and duration) of movies, episodes and free movies (200 entries). It resumes after 30 s unless fewer than 60 s remain, saves every 8 s, forgets a title when it ends, and the title row shows "continue at m:ss".
- **Wider playback:** `openStream` tries the channel's `url`; raw MPEG-TS (`.ts`, `c.ts`, or a link EYE3 Link wraps) goes to mpegts.js `1.7.3` (jsDelivr, loaded on demand), HLS to hls.js or native; if a stream fails and the channel has `alt` (EYE3 Link adds the other format for Xtream and for M3U `.ts` links), it is tried once. Xtream live uses `allowed_output_formats`: HLS first with TS as fallback, TS only when the panel offers nothing else. `http://` streams on the https page are fetched through EYE3 Link (`/stream?u=…&t=<token>`), or the screen says to start it. A stall watchdog reopens a frozen stream (3 times, then says so). Verified in real Chrome on a GitHub runner with real files (TS, HLS, dead link).
- **Big playlists:** a file over 3 MB, or one that would pass the 2000 channels of "My channels", is stored in IndexedDB (`eye3-library`, up to 300,000 channels, shown as its own category, removable in the Playlist maker; not synced). EYE3 Link reads lists up to 160 MB (`.gz` too), sends up to 100,000 rows and reports `total`/`truncated`. Playlist headers (`#EXTVLCOPT` user agent/referrer, `#EXTHTTP`, Kodi `url|User-Agent=…`) are kept by Link per channel (`h=<id>` on `/stream`, also for HLS segments); only User-Agent, Referer, Origin and Cookie are allowed and line breaks are stripped.
- **Other keys in Live TV:** `P` previous channel, `X` picture shape, `A` audio track, `T` subtitles. Search ignores accents and word order. A series plays the next episode after a 6 s countdown (Esc stops it).
- **Support:** Settings → Help → "Copy support report" (logins, passwords, MACs and tokens are scrubbed) and `home/send-files.html` (how to send files over the chat limit: zip first, then split into parts under 25 MB; never put passwords into a public place).
- Still on the "pro" list: recording and catch-up, and licence activation / white-label (needs a licence server and code signing, which cost money). Ship no channels or movies of the product's own.

Accounts can set a custom User-Agent (`ua` on every Link call and on its streams).

## Language (English only)
EYE3 Home runs in **English only** by request: there is no language setting, `startLang()` ignores the browser language and clears any saved `eye3.home.lang`. The paragraph below describes the dormant engine, kept so a language can be switched back on later; do not re-add a visible language switch without the owner asking.

EYE3 Home has a small translation engine in `home/index.html` (`applyLang`, `lookup`, a MutationObserver) and dictionaries in `home/i18n-fr.js` and `home/i18n-ar.js` (loaded on demand, cached by `home/sw.js`). The app keeps its English strings in code; the engine translates text nodes and `placeholder` / `title` / `aria-label` / `alt` attributes **as they are created**, matching the whole English string (whitespace collapsed) against `exact`, then `patterns` (regex → function, for messages with numbers or names), then bullet and " · " parts. Switching back to English restores the original text exactly. Language comes from Settings → Language (stored in `eye3.home.lang`) or, the first time, the browser language; unsupported languages stay English; Arabic sets `dir="rtl"` (layout uses CSS logical properties; tracked letter-spacing is removed for Arabic). Rules: mark **data** (channel, account, station and file names, the clock/date, example URLs, brand and tool names, the pairing code) with `translate="no"` (helper `nt()`), because a channel called "News" must never be translated; use `tr()` for browser `prompt`/`alert` text; when you add or change a visible English string, add the same key to **both** dictionary files and check Home in French and Arabic for leftover English (loop over the screens and list text nodes that were not translated). Option `value`s must stay English: only their visible text is translated. Translations were written by an AI and should be reviewed by a native speaker. The phone remote, the TV portal, Bridge and the main EYE3 Vision app are not translated yet.

Home also honours direct links `home/?add=m3u|xtream|mag` (opens IPTV accounts on that type) and `?add=playlist` (opens the Playlist maker). They only open the form: never prefill or save anything from the URL, and never add a link for the Explicit section.

## Playlist maker
Live TV → Playlist maker (`#ov-maker`) lets a viewer add their own channels by hand (name, link, group, logo, tvg-id), import an M3U file (the file input has no `accept` filter on purpose: iOS greys out `.m3u` files when one is set), and a PDF (text is read in the browser with pdf.js `3.11.174` from jsDelivr, loaded only when a PDF is picked; M3U lines in the PDF are parsed as M3U, otherwise every http(s) link becomes a channel named by the text before it or the line above; scans without text, password-protected PDFs and a failed CDN load give an inline message; 25 MB / 150 pages limit; nothing is uploaded), and export an `.m3u` (favourites, the channels listed in Live TV, or their own channels) to use in SS IPTV, VLC or TiviMate. Stored in `eye3.home.mychannels`, shown as the own category "My channels". Rules: nothing is uploaded; exports never include streams from the viewer's accounts (`LINK_BASE` URLs carry a private token); adult entries are neither listed nor exported while the Explicit section is locked, and import messages count visible channels only; attribute values are sanitised so a name cannot break the file; no DRM / license-key fields (EYE3 cannot play DRM and must not help configure protected streams). The idea came from the MIT-licensed imrsaleh/Easy-M3U-Playlist-Creator (a Tkinter tool); no code was copied.

## Sync phone and laptop
Settings → Sync phone and laptop (`openSyncInfo`, code in `eye3.home.sync`, state in `eye3.home.sync.state`) keeps "My channels" and favourites the same on two of the viewer's devices. One device creates a 12-character code, the other types it (a `home/#sync=CODE` link only pre-fills the form; the viewer presses Start). The code is never sent: it derives the relay topic (`eye3sync-` + SHA-256) and, separately, an AES-GCM key (PBKDF2, 150k iterations). A snapshot `{v, dev, ts, mine, favs}` is gzip-compressed, encrypted and sent as chunks of at most 3000 characters (`S1|sid|i|n|data`) through the free ntfy relay (`?signal=` honoured on localhost only, as for the phone remote); the receiver reassembles, decrypts and runs `syncClean` (plain strings and http(s) links only, bounded sizes, no `LINK_BASE` links) before applying. The first connection merges the two lists (union); after that the newest snapshot replaces the list, so deletions travel too (`ts` is a Lamport-style counter, not trusted clock time; echoes of one's own `dev` are ignored). **Never sync IPTV account logins, passwords, MAC addresses, the Explicit PIN or health results**, and never add commands to the phone-remote whitelist for this. Anyone with the code can read and change the synced lists, so the code is shown only in that dialog.

## Pro pack (welcome, profiles, guide grid, multi-view, cast, TV tools)
- **Welcome** (`openWelcome`, flag `eye3.home.setup`): a once-only first-run screen with four ways to start (free channels, add an account, import a playlist or PDF, set up a TV or box). It never shows for a viewer who already has an account, playlist, favourites or has used EYE3 Link (`maybeWelcome` sets the flag instead). Settings → Setup guide reopens it. The test harness seeds `eye3.home.setup=1` so other tests are not covered by it.
- **Profiles and the parent PIN** (`eye3.home.profiles`, active one in `eye3.home.profile`, PIN in `eye3.home.parentpin`, salted SHA-256, 4-8 digits, 5 tries then a 30 s wait): every profile can hide categories (filtered once in `buildAll`, so counts, search, countries and favourites all respect it); a kids profile also drops every adult channel, refuses the Explicit section and Movies & series, and needs the parent PIN to leave. Editing profiles needs the PIN once one is set; a kids profile cannot be saved without one. Never sync profiles or the PIN, and never add a visible Explicit entry point.
- **Guide grid** (key `D`, `#ov-grid`): the first 40 channels of the current list against 3 hours, programmes from `epgItems` (Xtream panel guide or XMLTV through EYE3 Link), 4 requests at a time; arrows move, Enter plays, Back returns to Live TV.
- **Multi-view** (key `M` adds the selected channel, `#ov-multi`): up to 4 HLS or mp4 channels with one sound (keys 1-4 or a click); raw TS streams are refused there; players are destroyed whenever the view closes.
- **Cast (`C`) and mini window (`O`)** use the browser's Remote Playback / AirPlay picker and Picture-in-Picture; streams that cannot be cast say so and point to the browser's own Cast menu.
- **Smart TV tools** (Settings): codec and HLS support of the screen, screen size, and a speed test that fetches a test file from Cloudflare only when the button is pressed.
- Dev tip: `ONLY="pro pack" node tests/e2e/home.js` runs one browser suite (start the mocks first, see `tests/run.sh`).

## EYE3 Box and the agent
- **Box kit** (`box/`): `install.sh` (Linux, Raspberry Pi, macOS; systemd user service or launch agents) and `install.ps1`/`install.bat` (Windows; Startup shortcuts) put EYE3 Link, a launcher (`eye3-start.sh`/`eye3-start.bat`: restarts after a crash and after exit code 75 = update installed; sets `EYE3_MANAGED=1`), `eye3-link.conf` (auto_fix and auto_update on) and a `playlists` folder on the computer behind the TV, and a Desktop link to EYE3 Home (`?splash=0&box=1`). By default the installer never touches the viewer's browser or its saved data (no separate browser profile, no fullscreen at sign-in); `--kiosk`/`-Kiosk` (the HDMI box behind a TV only) also opens Home fullscreen at every start. The program comes from the kit folder (USB stick), else a SHA-256-checked download from the `eye3-link-latest` release. `--dry-run`/`-DryRun`/`--uninstall` exist; `EYE3_NO_SERVICE=1` skips the start-up entries (tests). The Philips Saphi TV cannot install anything from USB: the kit is for the HDMI box, and docs must say so. `link-build.yml` publishes `eye3-link-version.txt` and the `EYE3-Box-*.zip` kits next to the programs.
- **Agent** (Link 1.7): `--auto-fix` (secure-DNS fallback on a failed lookup, the only auto-fix; never a VPN), `--auto-update` (frozen program only; fetch `eye3-link-version.txt` + `SHA256SUMS.txt` + asset, verify SHA-256, stage `eye3-link.update`, swap at the next start, only after 180 s without streaming), `--playlists`, `--config`; endpoints `/api/health`, `/api/agent`, `/api/update`, `/api/restart`, `/api/local`. Home polls `/api/health` every 30 s (chip `#agentchip`, Settings → EYE3 agent) but only for viewers who used Link before (`eye3.home.link`, an account, or `?box=1`); a new private token means Link restarted, so Home reloads accounts and the folder. Restart is offered only when Link says it is managed.
- **Playlists folder:** the viewer's OWN files. Files appear as their own lists in Live TV; adult entries (`x`) obey the Explicit rules (never listed, counted or named while locked). The repo ships no adult list and no playlists (`box/playlists/` holds a README only).
- **Do not** wire in scrapers or "agents" that harvest other people's adult or pirated lists from GitHub or the web, and do not bundle adult sources in the repo or the kit. The agent fixes the app and its own connection; it does not collect content.

## Explicit (18+) section and connection checks
- The explicit section is hidden on purpose: it has **no visible button**. It opens by double-clicking (or double-tapping) the eye logo (`#brand`) or with Shift+X, shows a dialog (`#ov-explicit`) with an "I am 18 or older" box and an optional PIN, and unlocks only for the current page load (a reload, the screensaver or the sleep timer lock it again). The PIN is stored salted + SHA-256 in `eye3.home.pin`; it stops casual use and is not strong security. Do not add a visible entry point for it.
- It reveals adult groups of the viewer's **own** accounts and playlists only. EYE3 never ships, lists or links adult channels: the public catalogue builder drops them, and the repo must not contain adult sources. EYE3 Link flags adult entries (`x: true`) instead of dropping them; Home keeps flagged channels out of every list, count, group, country, favourite and search unless the section is unlocked, and shows them only inside the "Explicit (18+)" category. Never leak their number while locked (the account row counts visible channels only). The TV portal still filters adult entries completely.
- "Check from my connection" (Live TV) asks EYE3 Link (`/api/probe`) whether each listed stream really delivers video from the viewer's own connection (through their `--proxy`/VPN if set), remembers the result for 24 hours in `eye3.home.health`, and can hide channels that failed. "Where is my connection?" (`/api/where`) asks ipinfo.io only when clicked. This is how geo-blocks are handled honestly: EYE3 does not include a VPN.

## Channel catalogue
`scripts/build_channels.py` + `.github/workflows/channels.yml` rebuild the free catalogue weekly (and on demand) on a GitHub runner, which has real internet: it reads the public iptv-org `index.m3u` and the Free-TV/IPTV `playlist.m3u8` (country-grouped; country names mapped to codes, categories guessed from names), keeps only HLS streams, drops adult channels, geo-blocked entries and streams that need custom headers, probes every stream (playlist, then the first variant, then its newest video segment) and keeps only the ones that really deliver video; links whose signed token (`exp=`) has expired are dropped. Output (committed by the workflow): `iptv/eye3-full.m3u` (for SS IPTV / Smart STB / TiviMate, all working channels grouped by category) and `iptv/channels.json` (compact, read by EYE3 Home and the TV portal; field `s`=1 means https, which is all a browser on https can play). The builder refuses to publish if fewer than 50 channels answer. `python3 scripts/test_build_channels.py` tests the probe offline. Do not hand-edit these generated files; change the script. Do not add paid, pirated or adult sources. `iptv/eye3.m3u` stays as the small hand-picked starter list.

## TV portal
`portal/c/index.html` is the Smart STB/MAG IPTV portal and `portal/check/index.html` is the TV capability check. Both must stay ES5 (no arrow functions, let/const, template literals, `?.`, `??`, spread) with plain CSS (no custom properties, flex, grid, `inset`, `min()`), because TV engines are old. The menu has Live TV (picks), All channels (category browser) and By country, both fed by `../../iptv/channels.json` over same-origin XHR, with Back returning to the previous list and a fallback to the built-in channels if the catalogue cannot load. Play through `gSTB.Play('ffmpeg ' + url)` when the MAG API exists, else HTML5 video. The portal also has a Phone remote receiver: it listens on an ntfy topic (`eye3rc-<code>`) via EventSource (XHR-poll fallback) and applies commands by synthesizing `document.onkeydown`; `remote/index.html` is the phone sender (POSTs plain commands). Keep both ES5-safe where they touch the portal. Only free public streams and the viewer's own playlist; never bundle paid or pirated sources.

## Rules
- Images must never be uploaded to a server. Keep analysis in the browser. Casting sends frames only peer-to-peer over the LAN (`RTCPeerConnection` with `iceServers: []`, never add STUN/TURN); ntfy carries only AES-GCM ciphertext keyed by the pairing code.
- Never auto-connect a sender from a `?join=` link; require a button press. The `?signal=` and `?pairTimeout=` overrides are honored on localhost only.
- Pin CDN versions exactly; never use `@latest`.
- Render untrusted text (file names, EXIF, OCR) with `textContent`, never `innerHTML`.
- A failed engine load must degrade to an inline message, not break the page.
- Deploys via `.github/workflows/pages.yml` on push to `main`.
